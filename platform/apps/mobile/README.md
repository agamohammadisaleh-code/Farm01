# مرغ‌یار موبایل (Expo)

اپ ثبت سالنی برای گوشی: **آفلاین‌فرست**. هر ثبت اول در SQLite گوشی ذخیره
می‌شود و بعد به سرور می‌رود؛ بدون اینترنت هیچ دکمه‌ای غیرفعال نمی‌شود و هیچ
داده‌ای گم نمی‌شود.

## اجرا

```bash
# از ریشه platform
npm install            # وابستگی‌های ورک‌اسپیس (شامل expo)
npm run build:domain   # بسته @farm/domain باید ساخته شده باشد
npm run typecheck:mobile
npm run start:mobile   # یا: cd apps/mobile && npx expo start
```

آدرس API در `app.json` → `expo.extra.apiUrl` تنظیم می‌شود. برای گوشی واقعی
`localhost` کار نمی‌کند؛ IP رایانه را بگذارید:

```json
"extra": { "apiUrl": "http://192.168.1.20:4000", "aiUrl": "http://192.168.1.20:8000" }
```

ورود با همان کاربر API، مثلاً `owner@farm.ir` / `Secret1234` (پس از `npm run seed -w @farm/api`).

## ساختار

```
App.tsx                        ناوبری، بوت از حافظه محلی، همگام‌سازی دوره‌ای
src/api/client.ts              fetch + توکن (SecureStore) + تفکیک خطای شبکه از خطای داده
src/storage/db.ts              SQLite: صف، ثبت‌ها، گله‌ها، یادآورها
src/sync/engine.ts             چسب صف ↔ API (منطق در @farm/domain/offline)
src/notifications/register.ts  زمان‌بندی اعلان محلی (منطق در @farm/domain/notifications)
src/screens/                   ورود، خانه، ثبت سریع، صف، تنظیمات
src/components/                کارت، دکمه بزرگ، صفحه‌کلید عددی فارسی
```

## چرا منطق در بسته دامنه است؟

صف، تلاش دوباره، ادغام تعارض و برنامه اعلان‌ها در `packages/domain` نوشته
شده‌اند (بدون وابستگی به React Native) و با `node --test` آزموده می‌شوند.
مزیت: می‌توان منطق آفلاین را در CI تست کرد، بدون شبیه‌ساز گوشی؛ و وب هم
می‌تواند همان کد را استفاده کند.

## آنچه باید یک‌بار روی دستگاه واقعی بررسی شود

این اپ در محیط توسعه بدون شبیه‌ساز اندروید/iOS نوشته و بررسی نوع شده است.
موارد وابسته به دستگاه که باید روی گوشی دیده شوند:

1. `expo-sqlite` و اجرای مهاجرت جدول‌ها در اولین باز کردن.
2. اعلان محلی (مجوز، کانال اندروید، نمایش در حالت بسته).
3. صفحه‌کلید عددی سفارشی و چیدمان RTL در دستگاه‌های مختلف.
4. رفتار وقتی گوشی در حالت هواپیما است و بعد شبکه وصل می‌شود.
